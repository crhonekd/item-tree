# Phase 13 — End-to-end (Phase A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove cache convergence and resilience end-to-end in Phase A by booting two Spring `ApplicationContext`s in one JVM that share the in-memory `InMemoryEventBus` and the in-memory H2 database, mutating from one instance and observing the other's cache.

**Architecture:**
- Boot two `ConfigurableApplicationContext`s manually via `SpringApplicationBuilder` (`WebApplicationType.NONE`, profile `dev`), per JUnit test method.
- A single `InMemoryEventBus` is shared across both contexts via a static `SharedBusHolder` + a `@Primary @Bean InMemoryEventBus` override in `E2ETestConfig` (bean-definition overriding enabled).
- H2 (`jdbc:h2:mem:itemtree;MODE=Oracle;DB_CLOSE_DELAY=-1`) is naturally shared because both contexts dial the same JDBC URL in the same JVM.
- Each context gets its own `InstanceIdProvider` (auto-random UUID), its own `TreeCache`, its own `EventConsumerService`, its own `ConnectionStateTracker`, its own `RefreshOrchestrator` — exactly the production shape.
- For the resilience scenarios, the test pre-mutates H2 directly through a non-publishing path (raw `JdbcTemplate` from instance B's `DataSource`), simulates outage + recovery on one instance, and observes its cache catches up via the orchestrator's full reload or delta refresh.

**Tech Stack:** Java 21, Spring Boot 3.4 `SpringApplicationBuilder`, JUnit 5 (`@ParameterizedTest` where applicable), AssertJ, Mockito, Awaitility, H2 (Oracle compat mode). No new production dependencies.

```java
package com.myxcomp.ice.xtree.e2e;

import com.myxcomp.ice.xtree.messaging.dev.InMemoryEventBus;

/**
 * Hands the same {@link InMemoryEventBus} instance to every caller within a JUnit test, so
 * two Spring contexts booted in the same JVM can publish/subscribe on one bus. The static
 * field is intentionally mutable: {@link #reset()} swaps in a fresh bus per {@code @BeforeEach}
 * so accumulated subscriptions from a prior test do not leak.
 *
 * <p>Not thread-safe across tests; JUnit Jupiter runs tests sequentially by default.
 */
public final class SharedBusHolder {

    private static InMemoryEventBus bus = new InMemoryEventBus();

    private SharedBusHolder() {}

    public static InMemoryEventBus get() {
        return bus;
    }

    public static void reset() {
        bus = new InMemoryEventBus();
    }
}
```

```java
package com.myxcomp.ice.xtree.e2e;

import com.myxcomp.ice.xtree.common.TimeMapper;
import com.myxcomp.ice.xtree.messaging.dev.InMemoryEventBus;
import org.mockito.Mockito;
import org.springframework.boot.test.context.TestConfiguration;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Primary;

import java.time.Instant;

import static org.mockito.Mockito.when;

/**
 * Test-only Spring configuration imported into each E2E-test {@link
 * org.springframework.context.ConfigurableApplicationContext}. Replaces two production beans:
 *
 * <ul>
 *   <li>{@link InMemoryEventBus} → delegates to {@link SharedBusHolder} so both contexts share
 *       one bus instance.</li>
 *   <li>{@link TimeMapper} → Mockito mock, pre-stubbed to a fixed {@code Instant} so bootstrap
 *       and refresh code that calls {@code timeMapper.now()} sees a deterministic clock. Tests
 *       can re-stub via {@code when(ctx.getBean(TimeMapper.class).now()).thenReturn(...)} to
 *       drive outage scenarios.</li>
 * </ul>
 *
 * <p>Requires {@code spring.main.allow-bean-definition-overriding=true} to override the
 * {@code @Component}-detected {@link InMemoryEventBus} and {@link TimeMapper} beans.
 */
@TestConfiguration
public class E2ETestConfig {

    public static final Instant DEFAULT_TEST_INSTANT = Instant.parse("2026-05-18T10:00:00Z");

    @Bean
    @Primary
    public InMemoryEventBus sharedInMemoryEventBus() {
        return SharedBusHolder.get();
    }

    @Bean
    @Primary
    public TimeMapper mockTimeMapper() {
        TimeMapper mock = Mockito.mock(TimeMapper.class);
        when(mock.now()).thenReturn(DEFAULT_TEST_INSTANT);
        when(mock.toOffsetDateTime(Mockito.any())).thenCallRealMethod();
        return mock;
    }
}
```

Note on `toOffsetDateTime`: Mockito `mock()` returns null for un-stubbed methods. `ItemNodeMapper` and `ItemNodeWithDataMapper` call `timeMapper.toOffsetDateTime(...)` (Phase 8 quality fix); make those calls fall through to the real implementation so HTTP mappers and any logging that touches it stay correct. Using `mock(TimeMapper.class)` instead of `spy(new TimeMapper())` keeps `now()` cleanly stubbable.

If `TimeMapper.toOffsetDateTime` is `static`, replace the `thenCallRealMethod()` line with a no-op; verify by reading `src/main/java/com/myxcomp/ice/xtree/common/TimeMapper.java` first.

```java
package com.myxcomp.ice.xtree.e2e;

import com.myxcomp.ice.xtree.ItemTreeApplication;
import org.springframework.boot.WebApplicationType;
import org.springframework.boot.builder.SpringApplicationBuilder;
import org.springframework.context.ConfigurableApplicationContext;

/**
 * Boots two independent {@link ConfigurableApplicationContext}s sharing the in-memory bus
 * (via {@link SharedBusHolder}) and the in-memory H2 database (via the same JDBC URL in the
 * same JVM). Each context owns its own {@link com.myxcomp.ice.xtree.common.InstanceIdProvider}
 * (auto-random UUID), its own {@link com.myxcomp.ice.xtree.cache.TreeCache}, its own
 * {@link com.myxcomp.ice.xtree.messaging.EventConsumerService}, and its own
 * {@link com.myxcomp.ice.xtree.messaging.ConnectionStateTracker}.
 *
 * <p>Callers must invoke {@link SharedBusHolder#reset()} <b>before</b> {@link #boot()} for
 * each test method so the bus has no stale subscriptions from a prior test.
 */
public final class TwoInstanceContexts implements AutoCloseable {

    private final ConfigurableApplicationContext a;
    private final ConfigurableApplicationContext b;

    private TwoInstanceContexts(ConfigurableApplicationContext a, ConfigurableApplicationContext b) {
        this.a = a;
        this.b = b;
    }

    public static TwoInstanceContexts boot() {
        ConfigurableApplicationContext a = launch("itemtree-A");
        ConfigurableApplicationContext b = launch("itemtree-B");
        return new TwoInstanceContexts(a, b);
    }

    private static ConfigurableApplicationContext launch(String label) {
        return new SpringApplicationBuilder(ItemTreeApplication.class, E2ETestConfig.class)
                .profiles("dev")
                .properties(
                        "spring.main.allow-bean-definition-overriding=true",
                        "spring.application.name=" + label
                )
                .web(WebApplicationType.NONE)
                .run();
    }

    public ConfigurableApplicationContext a() { return a; }
    public ConfigurableApplicationContext b() { return b; }

    @Override
    public void close() {
        try { a.close(); } catch (RuntimeException ignored) { /* best effort */ }
        try { b.close(); } catch (RuntimeException ignored) { /* best effort */ }
    }
}
```

## Risks and mitigations

1. **Bean override semantics.** `@Primary` + `spring.main.allow-bean-definition-overriding=true` is the documented Spring path, but if a future Spring upgrade tightens overrides, prefer a `BeanDefinitionRegistryPostProcessor` that explicitly removes the `@Component` `InMemoryEventBus` definition before registering the shared one. Cost: ~10 LOC, no behaviour change.

2. **H2 sharing across contexts and tests.** The URL is `jdbc:h2:mem:itemtree;MODE=Oracle;DB_CLOSE_DELAY=-1` (kept alive even when no connections are open). Each context's `spring.sql.init.mode=always` re-runs `data.sql`, which begins with `DELETE FROM ITEMTREE`. Inserts from a prior test are wiped at the next context boot — good for isolation. Within one test, if A inserts after B has bootstrapped, B's cache learns about it only via the bus (Tasks 4-6) or via direct H2 mutation + reconcile (Tasks 7-8).

3. **Bus subscription leakage across tests.** `LocalLoopbackEventConsumerStarter` subscribes `EventConsumerService::processPayload` to the bus on `@Order(2)` startup. The `InMemoryEventBus` has no `unsubscribe` API. We solve this by giving each test a *new* bus instance via `SharedBusHolder.reset()` in `@BeforeEach`. The previous test's bus (with its dead subscriptions) is garbage-collected once both contexts close.

4. **Mocked `TimeMapper.toOffsetDateTime` is `null`.** `ItemNodeMapper` calls this in HTTP DTO assembly. We boot `WebApplicationType.NONE`, so the mappers are not exercised in any of the planned tests. The `thenCallRealMethod()` line in `E2ETestConfig` is defensive — if the verification fails because the method is `static` (`TimeMapper.toOffsetDateTime` may be a static helper), remove that line and adjust as needed.

5. **Phase-12 `RefreshEndpointAccessFilter`.** The filter sits behind a `FilterRegistrationBean` and isn't triggered without HTTP requests. `WebApplicationType.NONE` keeps it out of the picture entirely. Confirmed safe.

6. **Slow boot.** Booting two full Spring contexts per test is ≈5-8 seconds each. 8 test methods × 8s ≈ 60s for the E2E class. Acceptable for a Phase A milestone. If it becomes painful, consider one-class-shared boot with explicit cache cleanup; do not optimise prematurely.
